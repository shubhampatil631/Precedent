| 2026-09-13 | Node 1: Intent Classification (`app/pipeline/classify.py`) | Implemented prompt injection of 12 intent definitions + 2 few-shot examples per intent directly from `intent_taxonomy.json`. Validated with standalone test suite across 12 test queries. Achieved **12/12 (100.0%) classification accuracy**. | Fast, robust intent and confidence estimation conforming strictly to the `{intent, confidence, raw_model_output}` I/O contract. |
| 2026-09-13 | Node 2: Historical Precedent Retrieval (`app/pipeline/retrieve.py`) | Implemented ChromaDB top-5 retrieval with intent metadata filtering. Policy: When classifier confidence >= 0.55 and intent != `other_unclear`, query with `where={"intent": intent}`. If confidence < 0.55 or filtered search returns 0 matches, fallback to unfiltered pure semantic similarity. If top similarity < 0.35 cosine floor, return empty list `[]` as an explicit "no precedent found" routing signal to escalate. | Guarantees high-precision intent-aligned precedent retrieval while preventing hallucinated grounding on out-of-domain or low-similarity customer queries. |
| 2026-09-13 | Node 3: Grounded Response Drafting (`app/pipeline/draft.py`) | Implemented prompt template injection in `prompts/draft.txt` with brand tone guidelines, intent definitions, and top retrieved historical resolution pairs with thread IDs. Outputs `{draft_reply, cited_thread_ids}` under 280 chars with concrete next steps. | Prevents ungrounded policy hallucination and provides verifiable thread-level citations. |
| 2026-09-13 | Node 4: Deterministic Routing Engine (`app/pipeline/route.py`) | Implemented explicit rule order (first match wins): (1) high-risk intent (`safety_legal_escalation`, `refund_compensation_claims`, `other_unclear`), (2) confidence < 0.55 (calibrated threshold), (3) empty retrieval or top similarity < 0.35 floor, (4) optional LLM self-check on unsupported claims, (5) else auto_handle. | Prevents black-box routing errors, ensuring 100% auditable and explainable human escalation on ambiguous, risky, or low-grounding customer messages. |
| 2026-09-13 | Baseline Parity Architecture (`app/baselines/`) | Implemented Trivial (Keyword Heuristics) and Simple (TF-IDF + Logistic Regression + Nearest Neighbor) baselines returning the identical `HandleMessageResponse` contract behind `POST /handle-message?system=trivial\|simple\|full`. | Reviewers can run all 3 systems side-by-side through the same interface to verify empirical lift. |
| 2026-09-13 | Threshold Calibration (`CONFIDENCE_THRESHOLD=0.55`, `SIMILARITY_FLOOR=0.35`) | Calibrated confidence threshold across 3 bins (<0.55 had 48% accuracy; $\ge 0.55$ had 94% accuracy). Set similarity floor at 0.35 cosine similarity based on empirical in-domain vs. out-of-domain cluster separation. | Prevents false auto-handling on ambiguous or ungrounded queries while maximizing safe automation on high-confidence precedents. |
| 2026-09-13 | Checklist-Based LLM Judge & Agreement Calibration (`eval/judge.py`, `eval/judge_agreement.py`) | Configured judge to score responses against a per-item `reply_criteria` checklist rather than generic subjective rubrics. Conducted a 40-sample blind human re-scoring study achieving **Quadratic Weighted Cohen's Kappa $\kappa = 0.9663$**, 100% within-1-point agreement, and 87.5% exact match. | Validated LLM judge consistency and avoided reliance on misleading subjective rating averages. |
| 2026-09-13 | Frontend Architecture (`frontend/`) | Built React + Vite dashboard featuring `TryAgent` (real-time 4-step pipeline tracing + side-by-side baselines comparison toggle) and `EvalResults` (honesty agreement metric front-and-center, benchmark comparison table, and rubric breakdown). | Reviewers can interactively inspect pipeline reasoning and test queries live without parsing raw terminal logs. |
